本版は v2 に対する敵対的検証の結果を反映した改訂である。主な変更点は次のとおり。

5. 勝率の目的量定義を、非決着試行を勝利へ変換しない dataset 契約と整合させた(§4.2、要判断)
6. 移動容易度チャネルの方向依存性、および価値マップが構成する

   Pareto regret の完全な定義、参照 front と最終再評価の seed 集合の紐づけを含めて拡充した(§9)
8. H3 の合接命題に intersection-union test の判定規則を追加し、
   H5 に permutation test と減衰バイアスの扱いを追加した(§7)
9. BattleSimulator の追加要件を、既存機能と新規要件に分離し、
   rules version への影響を明記した(§12)
10. H5 の内部妥当性検査から検定手続きを欠いた主張を撤回し、
    permutation test の結果へ紐づけた(§7, §13)
11. 表記を `rules version 1.0` へ統一し、本文へ inline citation を追加した(§14)

## 1. 文書の目的

本書は、BattleSimulator を用いて検証する研究の背景、問題設定、研究質問、
仮説、および主張範囲を定める。

本研究の第一段階では、BattleSimulator rules version 1.0 を実験対象となる
確率的シミュレーターとして扱う。現実の戦闘を予測するモデルとしてではなく、
空間的な多主体相互作用を含む、再現可能で監査可能なベンチマーク環境として
使用する。

シミュレーション自体の正本は `docs/simulation-rules.md`、現行実装の仕様は
`docs/current-spec.md`、代理モデル用データの契約は
`docs/dataset-contract.md` とする。

## 2. 研究背景

### 2.1 問題領域

多主体相互作用を伴う空間配置最適化は、ロボティクス、群集解析、ゲーム AI
などで現れる。これらの問題では、主体の初期配置、環境の空間構造、主体間の
相互作用が結果へ複合的に影響する。また、勝率、生存率、所要時間、損耗などの
複数の評価指標が競合するため、多目的最適化問題として扱う必要がある。

シミュレーションによる候補解の評価には計算コストがかかる。さらに確率的な
シミュレーターでは、1つの候補解について複数 seed の反復評価が必要になる。
そのため、進化的多目的最適化が要求する多数の候補評価が、実用上の
ボトルネックになる。

この問題に対して、シミュレーターの入出力関係を近似する代理モデルを探索へ
組み込む surrogate-assisted evolutionary optimization(SAEA)が研究されて
きた。代表的な方法では、限られた真のシミュレーション結果から目的値を直接
予測する回帰モデルを構築し、その予測値を候補解の評価または事前選別に
利用する。

一方、代理モデルの平均的な回帰誤差が小さいことと、その代理モデルが良い探索を
誘導することは同値ではない。探索では、入力空間全体の平均誤差よりも、次の性質が
重要になる。

- 有望な候補間の順位を正しく保存すること
- Pareto 優越関係を正しく推定すること
- 未探索領域に偽の最適解を作らないこと
- 真の Pareto front 近傍で必要な解像度を持つこと
- 特定の探索軌跡が生む分布シフトに耐えること

代理モデルだけで目的値を置き換えると、代理モデル上の Pareto front が真の
目的関数の Pareto front と対応しない、偽の最適解へ収束する可能性がある。
このため、代理モデルは単独の回帰器としてではなく、真の評価との切り替え方を
含む探索システムとして評価する必要がある。SAEA の性能がモデル管理戦略に
強く依存することは先行研究でも指摘されており[4]、本研究の実験設計はこの点を
統制および感度分析の対象とする(§8, §9)。

予測誤差ではなく最終的な意思決定品質を重視する問題意識は、
predict-then-optimize や decision-focused learning とも共通する[2, 3]。
本研究はこの問題意識を、確率的な多主体空間配置と多目的進化的最適化へ適用する。

### 2.2 空間的中間表現に関する先行概念との関係

空間的な中間表現を介して意思決定を誘導する枠組みには、複数の先行概念が
存在する。

- ゲーム AI 分野の influence map[9] は、地形や勢力の影響を空間グリッド上の
  スカラー場として表現し、行動選択に用いる。ただし多くは設計者が定義した
  規則に基づく手作りの場であり、最終目的値からの学習を前提としない。
- ロボティクス分野の学習型 costmap[8] や、逆強化学習(IRL)による報酬マップの
  推定[7] は、専門家軌跡または結果から空間的な価値場を学習する。ただし対象は
  主に単一主体の経路計画であり、多目的最適化の代理評価器としての利用や、
  真評価予算下での探索性能による評価は主眼でない。

本研究の位置づけは、これらの空間的中間表現の考え方を、確率的多主体
シミュレーターに対する surrogate-assisted 多目的進化最適化へ移植し、
「中間表現の構造が探索性能へ与える効果」を統制実験で評価する点にある。
すなわち、価値マップという表現形式そのものの新規性ではなく、SAEA の
モデル構造としての効果検証を貢献として主張する。この位置づけに対応して、
学習を伴わない解析的な価値マップを比較対象に含める(§8)。

## 3. 研究上の着眼点

目的値を直接出力するブラックボックス型代理モデルは、地形、配置、主体間の
相互作用を単一の写像として学習する。この構造では、地形のどの領域が移動、
射線、遮蔽、高低差、objective 到達へ影響したかが明示されない。

本研究では、地形が主体間相互作用へ与える影響のうち、**配置に依存しない
地形固有の成分**を空間的な中間表現として分離する。この中間表現を価値マップと
呼び、価値マップを介して目的値を推定するモジュール型代理モデルを
「価値マップ型代理モデル」と定義する。

価値マップは、以下のような配置非依存の量を空間グリッド上のチャネルとして
表現する。

- 移動容易度または移動コスト
- 各セルからの可視性および射線の価値
- 高低差による交戦上の優位性
- cover の価値
- objective への到達性または占有価値

`docs/simulation-rules.md` の rules version 1.0 では、移動補正は
「移動元から移動先への標高勾配」から計算され、上りの場合だけ
`1 / (1 + rise)` を移動量へ掛ける**方向依存(異方性)の量**である。したがって
移動容易度を 1 チャネルの per-cell スカラー場として表現すると、この非対称性を
原理的に表現できない。既定では移動容易度を方向別チャネル(近傍 4 方向または
8 方向)として持つ。1 チャネルのスカラーへ縮約する変種を用いる場合は、
方向情報を失う損失付き近似であることを明示する。

**敵味方の配置に依存する相互作用価値は、価値マップのチャネルには含めない。**
配置依存の相互作用は、価値マップと候補配置を入力とする下流の予測器
\(h_{\psi}\) が担う(§4)。この分離により、価値マップは「地形 \(t\) と
文脈 \(c\) のみの関数」として一貫して定義される。配置を条件とする動的な
価値マップ \(V(t, x, c)\) は設計上の変種として考えられるが、目的値直接
予測型との構造差が縮小し比較の解釈が難しくなるため、第一段階の対象外とし、
将来課題とする。

価値マップは、入力地形を可視化しただけのものではない。候補配置と組み合わせて
目的値を予測し、最適化探索を誘導するための中間表現である。

ただし、最終目的値だけから学習した潜在マップは一般に一意に定まらない。
したがって、補助教師、介入に対する整合性、空間変換に対する同変性などを導入
しない限り、価値マップを因果的または人間に解釈可能な地形効果であるとは
主張しない。

## 4. 問題設定

### 4.1 定式化

候補となる空間配置を \(x\)、地形および固定された環境条件を \(t\)、
シミュレーション内の乱数を \(\xi\) とする。シミュレーターの出力を

\[
y = S(x, t, \xi)
\]

と表す。

配置 \(x\) には実行可能制約を課す。少なくとも、配置可能セル集合への所属、
ユニット間の重複禁止、チーム別の初期配置領域を制約として明示する。制約は
最適化器では実行可能解への修復または制約付き生成で処理し、代理モデルの
学習データには実行可能解のみを含める。制約処理の方式は全比較対象で統一する。

### 4.2 目的量の型

最適化に用いる真の目的関数は、目的量の型ごとに次のとおり定義する。

`rules version 1.0` の `winner_team_ids` は、0 個(未決着)から複数個(同 tick
複数 objective 達成)までを取りうる team ID の tuple であり、終了理由は
`elimination`、`mutual_destruction`、`timeout`、`stalemate` の 4 種である。
`docs/dataset-contract.md` は "Timeout and stalemate remain separate labels
and must not be converted to wins" と定め、非決着を勝利へ変換することを
禁じている。したがって勝率を単純な Bernoulli 成功確率へ縮約する前に、
非決着試行の扱いを定める必要がある。

> **要判断**: 対象 team の勝率は「対象 team が単独勝者である試行数 ÷
> **全試行数(非決着を含む)**」と定義することを推奨する。非決着試行を
> 分母から除外すると、非決着になりやすい候補ほど見かけの勝率が過大評価される。
> この定義であれば、非決着は「失敗」側へ計上され、Bernoulli 成功確率としての
> 扱いが dataset 契約と両立する。相打ち(`mutual_destruction`)を勝敗いずれの
> 成功としても扱わないことも同様の理由による。

- 勝率などの二値結果に由来する量は、上記の定義に従って Bernoulli 結果の
  成功確率として扱い、代理モデル側は確率出力の分類器として学習し
  calibration を評価する。
- 生存率、損耗、戦闘時間などの連続量は、seed に関する期待値
  \(f(x, t) = \mathbb{E}_{\xi}[S(x, t, \xi)]\) として扱う。戦闘時間は
  `timeout` 試行を打ち切り値として扱うか除外するかを、目的として採用する
  場合に別途定める。
- 分位点などその他の分布統計量は第一段階では使用しない。

実際には有限個の共通 seed による Monte Carlo 推定を用いる。

### 4.3 代理モデルの構造

目的値直接予測型の代理モデルは、概念的には

\[
\hat{y} = g_{\theta}(x, t)
\]

と表す。価値マップ型代理モデルは、

\[
V = v_{\phi}(t, c), \qquad
\hat{y} = h_{\psi}(x, V, c)
\]

と表す。ここで \(V\) は配置非依存の空間的価値マップ、\(c\) はユニット構成、
能力値、戦術方針などの文脈情報である。配置依存の相互作用の推定は
\(h_{\psi}\) が担う。

第一段階では §4.4 の方針によりユニット構成と戦闘ルールを固定するため、
文脈 \(c\) は実質的に定数となり、\(V = v_{\phi}(t)\) に縮退する。この条件下で
価値マップ型代理モデルが直接予測型と異なる点は、地形由来の情報がすべて
チャネル数 \(K\) の空間 \(V\) を経由してから \(h_{\psi}\) へ渡される、
という **bottleneck 構造**そのものである。したがって処置の実体は
「価値マップという表現形式」ではなく「チャネル数 \(K\) の空間 bottleneck を
挟む構造制約」であり、\(K\) と bottleneck の挿入位置を比較対象間で統制すべき
設計変数として扱う(§8.3)。

### 4.4 最適化変数と目的の選定

第一段階では、ユニット構成と戦闘ルールを固定し、初期配置 \(x\) を主な
最適化変数とする。

2目的の選定は、実験開始前に予備データで実施する。多目的最適化における
「良い目的対」とは、互いに独立ではなく、一方の改善が他方の悪化を伴う
trade-off 関係にある対である。両目的を最大化方向へ正規化してそろえた場合、
そのような trade-off は Spearman 順位相関 \(\rho\) が**強く負**である対として
現れる。したがって \(|\rho|\) を最小化する基準は、最も強い trade-off を持つ
候補対を積極的に排除してしまい、目的が指す方向と逆になる。

> **要判断**: 目的対の選定基準を次のとおり修正することを推奨する。
>
> 1. 候補目的をすべて最大化方向へ正規化する
> 2. \(\rho > 0.7\) の対を冗長として除外する(同一方向にほぼ単調な対を除く)
> 3. 残る候補対のうち、\(\rho\) が最も負である対を採用する
> 4. 予備データの範囲で trade-off(一方の改善が他方の悪化を伴う候補対)が
>    観測されることを採用の条件とする
> 5. どの候補対も基準2を満たさない場合(すべて \(\rho > 0.7\))の fallback を
>    事前に定める。例えば、予備データの地形族数を増やして再評価する、
>    または目的候補(勝率、生存率、損耗、戦闘時間、力の交換比など)を拡張する
>
> 選定は本実験のデータ取得前に確定し、以後変更しない。

## 5. 研究目的

本研究の目的は、価値マップ型代理モデルの回帰精度が目的値直接予測型モデルより
高いことを示すことではない。代理モデルの構造が、限られた真の評価予算の中で
探索軌跡と最終的な解分布へ与える影響を明らかにすることである。

本研究は、次の二層で構成する。

**検証的検証(confirmatory)**: 事前に方向性を指定した仮説 H1、H1b、H1c、H3、
H4 を、§9 の統計的検定計画に従って検定する。特に H1b は、提案モデルの
主張が成立するための必要条件(§8.1, §13)を検定する仮説であり、本研究の
主張の可否を直接左右する。

**探索的分析(exploratory)**: 以下は仮説検定の対象とせず、記述的および
相関的な分析として報告する。

1. どの地形複雑度、学習データ量、評価予算、確率分散において検証的仮説の
   効果が現れるか、または現れないか(H1c は学習データ量については検証的
   仮説として §7 で別途扱う)
2. 回帰精度指標、順位保存指標、最適化性能の間の関係(H2 に対応)
3. 代理モデルが選択する候補領域と探索軌跡の違い
4. 価値マップの予測変化と局所介入結果の整合性の内部妥当性(H5 に対応)。
   整合性は目的値レベルで測定し(§7)、マップ自体の空間的変化の分析は
   定性的な可視化にとどめる

探索的分析の結果は効果の条件依存性に関する仮説生成として扱い、確認には
独立した後続実験を要することを明記する。

## 6. 研究質問

### RQ1: 探索効率(検証的)

価値マップ型代理モデルは、目的値直接予測型代理モデルと比較して、同一の真の
シミュレーション評価予算で、より良い真の Pareto front を獲得できるか。

### RQ1b: 学習された価値マップの寄与(検証的)

学習された価値マップ \(v_{\phi}\) を用いる提案モデルは、地形から解析的に
計算した手作り価値マップに同一の \(h_{\psi}\) を接続した基準モデルより、
同一の真シミュレーション評価予算で真評価後の hypervolume を大きくするか。

### RQ1c: bottleneck の効果と学習データ量の関係(検証的)

価値マップ型代理モデルと目的値直接予測型代理モデルの最適化性能の差は、
学習データ量が増えるにつれて縮小するか。

### RQ2: 精度指標と最適化性能の関係(探索的)

テストデータ上の回帰精度指標(RMSE、MAE)は、順位保存指標および最終的な
最適化性能をどの程度予測するか。精度指標が同水準でも最適化性能が乖離する
事例は観測されるか。

### RQ3: 解分布(検証的)

価値マップ型代理モデルは、真の目的空間における収束性を損なわずに、解集合の
多様性または被覆範囲を改善するか。

### RQ4: 汎化(検証的)

価値マップ型代理モデルは、学習に含まれない地形族や配置条件において、
目的値直接予測型代理モデルより小さい最適化 regret を示すか。

### RQ5: 中間表現の整合性(探索的・内部妥当性)

地形への局所的な介入に対して、価値マップ型代理モデルが予測する目的値の変化は、
真のシミュレーション結果の変化と、空間シャッフル対照より強く整合するか。

## 7. 検証仮説

### 検証的仮説

#### H1: 評価効率仮説

同一の真シミュレーション評価回数において、価値マップ型代理モデルを用いた
探索は、目的値直接予測型代理モデルを用いた探索より、真評価後の
hypervolume を大きくする。比較対象は §8.1 の比較対象5(直接予測型)と
比較対象7(提案モデル)とする。

帰無仮説 H1-0: 両モデル間で真評価後の hypervolume の分布に差がない。

#### H1b: 学習された価値マップの寄与仮説

同一の真シミュレーション評価回数において、提案モデル(比較対象7)を用いた
探索は、解析的価値マップ基準(比較対象6)を用いた探索より、真評価後の
hypervolume を大きくする。比較対象6は §4.3 と同じ bottleneck 構造(同一
チャネル数 \(K\)、同一 \(h_{\psi}\))を持ち、\(v_{\phi}\) の部分だけを
学習済みモデルから解析的な手作りマップへ置き換えたものである。

帰無仮説 H1b-0: 両モデル間で真評価後の hypervolume の分布に差がない。

H1b は §8.1 および §13 が定める主張ゲートに直結する。H1b が棄却されない
場合、学習された価値マップの寄与は主張しない。

#### H1c: bottleneck の学習データ依存性仮説

チャネル数 \(K\) の空間 bottleneck を課す提案モデルは、bottleneck を持たない
直接予測型モデル(比較対象5)と比べて、学習データ量が少ない領域では
hypervolume が優る一方、学習データ量が増えるにつれてその差が縮小する。

帰無仮説 H1c-0: 提案モデルと直接予測型モデルの hypervolume 差は、学習データ量
に対して単調に縮小しない(差が拡大する、または一定である)。

H1c は、bottleneck 構造を帰納バイアスとして解釈する立場からの反証可能な
予測であり、学習データ量を操作した複数条件での H1 相当比較として検定する。

#### H3: 解分布仮説

価値マップ型代理モデルを用いた探索は、目的値直接予測型モデルと比較して、
次の2条件を同時に満たす。

- (i) 収束性(IGD+[10])が非劣である(事前に定めた非劣性マージン \(\delta\)
  以内)
- (ii) 真の目的空間における解集合の多様性指標が改善する

帰無仮説 H3-0: (i) または (ii) が成立しない。

H3 は (i) と (ii) の合接命題であり、多様性の改善が収束性の犠牲によって
得られたものでないことを要求する。「異なる候補領域を探索する」という
探索軌跡の記述は仮説から除外し、探索的分析(§5)として報告する。

判定は intersection-union test とする。(i) の非劣性検定と (ii) の優越性検定を
それぞれ有意水準 \(\alpha\)(§9.2)で個別に実施し、**両方**が棄却されて
初めて H3-0 を棄却して H3 を採択する。合接命題であることを理由に \(\alpha\)
を2成分へ分割することはしない(intersection-union test は全体の第一種の
過誤を各成分の \(\alpha\) 以下に抑えるため、分割の必要がない)。

#### H4: 未知地形汎化仮説

scenario family 単位で分離した未知地形において、価値マップ型代理モデルは
目的値直接予測型モデルより、真評価後の hypervolume gap および Pareto regret
を小さくする。

帰無仮説 H4-0: 未知地形における最適化性能に差がない。

### 探索的分析項目(検定対象外)

#### H2(再定式化): 精度指標の不十分性に関する分析

前版の「回帰精度が同程度である場合」という条件付けは、精度がモデル構造の
下流変数であるため post-treatment conditioning となり、因果解釈を損なう。
そこで H2 を次の相関構造の分析へ再定式化する。

複数のモデル構造とモデル容量にわたり、テスト回帰精度(RMSE、MAE)と、
順位保存指標(順位相関、pairwise dominance accuracy、top-k recall)および
最適化性能(hypervolume、Pareto regret)の散布を提示し、回帰精度指標が
最適化性能の十分な予測子でないことを示す事例の有無を分析する。

これは検定を伴う仮説ではなく、指標選択に関する実証的知見の提示である。

#### H5(再定式化): 空間介入整合性の内部妥当性検査

遮蔽物、高所、移動困難領域などの局所的な地形介入の集合
\(\{\Delta t_j\}\) を事前に定義し、各介入について次を比較する。

- 代理モデルが予測する目的値の変化 \(\Delta \hat{y}_j\)
- 真のシミュレーションによる目的値の変化 \(\Delta f_j\)

整合性の統計量は、介入集合にわたる \(\Delta \hat{y}_j\) と
\(\Delta f_j\) の Spearman 順位相関、および符号一致率とする。対照条件は
(a) 価値マップの空間位置をシャッフルしたモデル、(b) 学習に用いていない
地形の価値マップを流用したモデルとする。

局所介入が迂回路の出現などの大域的な戦術変化を引き起こす場合、価値マップの
変化は非局所になりうる。このため「介入箇所近傍のマップ変化量」を整合性の
定義に用いることはせず、整合性は目的値レベルで測定する。マップ自体の空間的
変化の分析は定性的な可視化にとどめる。

整合性統計量の推定には次の2点を適用する。

- 介入集合 \(\{\Delta t_j\}\) は少なくとも 20 件以上を事前に定義し、
  介入の種類(遮蔽、高所、移動困難)ごとに均等に配分する
- \(\Delta f_j\) は有限 seed 数の Monte Carlo 推定であるため、seed 数が
  少ないと測定誤差により Spearman 順位相関が系統的に過小評価される
  (減衰バイアス)。介入あたり seed 数を、主比較(§8.5)と同数以上に固定し、
  観測された相関を減衰バイアスの下界として報告する

対照条件との差については、提案モデルと対照条件(a)(b)それぞれとの整合性
統計量の差を、介入集合を単位とした permutation test(介入とモデル出力の
対応をランダム化する)で評価し、有意水準は §9.2 の副次検定として扱う。
この permutation test は多重比較の主要な検定族(H1、H1b、H3、H4)には含めない
副次的な内部妥当性検査であり、有意であった場合に限り「対照条件を上回る
整合性を示した」と主張する。有意でない場合、対照条件に対する優位性は
主張しない。

H5 は提案手法の内部妥当性検査であり、モデル間比較の主張には用いない。

## 8. 比較実験の原則

### 8.1 比較対象

最低限、以下を比較対象とする。

1. ランダムサーチ(真評価予算をランダム候補の評価に全て消費する下限基準)
2. 真のシミュレーターだけを用いる多目的最適化(代理モデルなし)
3. GP ベースの標準 SAEA 手法(ParEGO[5] および K-RVEA[6]、実装可能性に応じて
   少なくとも一方)
4. 固定長集約特徴から目的値を直接予測する基準モデル
5. 価値マップ型と同じ空間入力を受け、目的値を直接出力する空間モデル
6. **解析的価値マップ基準**: 可視性解析、経路コスト場、高低差場などを地形
   から解析的に計算した手作り価値マップに、提案モデルと同一の \(h_{\psi}\)
   を接続したモデル。チャネル数、bottleneck の挿入位置、\(h_{\psi}\) の
   アーキテクチャは比較対象7と同一にそろえる(§8.3)
7. 価値マップを中間出力する提案モデル
8. 価値マップの空間位置をシャッフルするアブレーション
9. 価値マップの構造制約(非負性、平滑性、チャネル意味論の固定など)のみを
   外し、bottleneck 幅 \(K\) は比較対象7と同一に維持したアブレーション

比較対象6は、学習された \(v_{\phi}\) の寄与を分離するための重要な基準で
あり、H1b(§7)の検定対象である。提案モデルが H1b で比較対象6を有意に
上回らない場合、学習された価値マップの寄与は主張しない(§13)。比較対象3は、
本問題に対する SAEA 標準手法の有効性水準を示し、提案手法の土俵の妥当性を
確認するために用いる。

空間入力を持たない基準モデル(比較対象4)だけとの比較で、価値マップ構造の
効果を結論しない。主要な構造比較は比較対象5と7の間(H1)、および比較対象6と
7の間(H1b)で行う。

比較対象9 は §8.2 が主比較を補助教師なしと定めることに対応して、
「補助損失を除いたアブレーション」ではなく「構造制約のみを除いたアブレーション」
として定義する。bottleneck 幅 \(K\) を維持したまま構造制約だけを外すことで、
効果が \(K\) によるものか、価値マップに課す構造的制約によるものかを分離する。

### 8.2 情報予算の統制

補助教師を用いるモデルは、event log などシミュレーター内部状態に由来する
追加情報を消費する。この情報量の差が構造の効果と交絡することを防ぐため、
次の規則を適用する。

- **主比較は補助教師なしの条件で行う。** 提案モデル(比較対象7)の主構成は、
  最終目的値のみから end-to-end で学習する。
- event log は真評価1回の無償副産物と位置づけ、補助教師を用いる構成を評価
  する場合は、直接予測型(比較対象5)にも同一の event log 由来特徴を補助
  損失として与えた対応構成を用意し、対で比較する。
- 補助教師ありの構成は副次的な変種として報告し、主張は主比較に基づく。

### 8.3 計算予算とハイパーパラメータの統制

- 学習可能パラメータ数は、比較対象5と7の間で ±10% 以内にそろえる。
- **bottleneck 幅 \(K\)(価値マップのチャネル数)を、比較対象6・7・9の間で
  同一に固定する。** \(K\) は §4.3 が定める処置の実体であるため、独立の
  設計変数として扱い、モデル構造とは別にアブレーション(複数の \(K\) 水準)
  の対象とすることができる。ただし主たる検証的検定(H1、H1b、H3、H4)は
  事前に固定した単一の \(K\) で実施する。
- 学習計算量(FLOPs または実測学習時間)の上限を共通に設定する。
  deep ensemble(§8.4)を用いる構成では、この上限を **ensemble member
  1個あたり**の学習計算量に適用し、アンサンブルサイズが同一である限り
  総学習計算量は比較対象間でアンサンブルサイズ倍にそろう。
- ハイパーパラメータ探索は、全モデルで同一の試行回数、同一の探索アルゴリズム、
  同一の検証指標を用い、試行回数を事前に固定して記録する。
- 回転・反転などのデータ拡張を用いる場合は、全学習型モデルへ同一に適用する。
  空間同変性を組み込む場合は、その有無を独立のアブレーションとして扱い、
  提案モデルだけの隠れた利点にしない。

### 8.4 モデル管理と infill 規則

SAEA の性能はモデル管理戦略に依存するため、次の2種類の infill 規則で
比較を実施する。

- 予測値ベースの infill(代理モデル上の非劣解候補を選択)
- 不確実性考慮型の infill(予測値と予測不確実性を組み合わせた獲得規則)

NN 系代理モデルの予測不確実性は deep ensemble[11](アンサンブルサイズは全
モデル共通)で推定する。GP ベース手法は自身の事後分散を用いる。

モデル間では、学習データ、真評価予算、初期サンプル、最適化アルゴリズム、
infill 規則をそろえる。

> **要判断**: H1、H1b、H3、H4 の検証的検定は、上記2水準のうち**どちらか1つ**
> を primary configuration として実施し、残る1水準は感度分析として報告する
> ことを推奨する(§9.1 の検出力計算と多重比較族のサイズは primary
> configuration のみを対象とする)。不確実性考慮型 infill は探索初期の
> 過学習に頑健であるとされ、価値マップの bottleneck が効くと想定する条件
> (H1c、学習データ量が少ない領域)により適合するため、**不確実性考慮型
> infill を primary configuration とする**ことを既定案とするが、最終決定は
> 予備実験でのモデル管理戦略間の性能差を見て確定する。

### 8.5 乱数と評価予算の配分

確率的評価の比較には共通乱数を用いる。同一候補または対応する候補は同じ
combat seed 集合で評価し、モデル間の差に対する乱数分散を抑える。CRN
(common random numbers[12])により run 間で対応関係が生じるため、§9.2 の
対応あり検定の前提となる。

固定予算下での「候補数 × seed 数」の配分は設計変数であり、モデル構造に
よって最適配分が異なる可能性がある。第一段階では配分を全モデル共通に固定し、
少なくとも2水準の配分(候補数重視、seed 数重視)での感度分析を実施する。
配分の適応的制御は将来課題とする。

> **要判断**: §8.4 と同様に、H1、H1b、H3、H4 の検証的検定は2水準のうち
> **候補数重視の配分**を primary configuration とすることを既定案とする。
> 代理モデルの構造差を検出するには、seed 数を減らして共通乱数下の候補数を
> 増やす方が、モデル間の予測差を反映した探索軌跡の違いを蓄積しやすいという
> 想定による。最終決定は予備実験で確定する。

## 9. 統計的検定計画

検証的仮説 H1、H1b、H1c、H3、H4 に対して、以下を事前に定める。すべて
§8.4/§8.5 の primary configuration の下で実施し、他の infill 規則・予算配分
の組み合わせは感度分析として §9 の多重比較族に含めない。

### 9.1 実験単位、反復、検出力

- 検定の単位は独立した最適化 run とする。
- run 間で初期サンプルと最適化乱数を変え、combat seed 集合は §8.5 の
  共通乱数規則に従う。

> **要判断**: 必要 run 数は事前の検出力計算で確定し、固定値として運用する。
> 既定案として、対応あり Wilcoxon 符号順位検定(§9.2)で
> Vargha-Delaney A12 = 0.71(中程度〜大の効果量)を最小検出したい効果量とし、
> 有意水準は §9.2 の多重比較補正後の実効 \(\alpha\)(地形族数を含む検定族
> サイズに依存、§11 で地形族数を固定する)、検出力 0.8 を目標として run 数を
> 算出する。予備実験の結果、この効果量を仮定した場合は各条件につき
> 独立乱数系列で **35 run 以上**を目安とする(地形族数と検定族サイズの
> 確定後に再計算し、この文書を更新する)。21 run という前版の数値は
> 検出力計算の根拠を欠いていたため置き換える。

### 9.2 検定手法

- hypervolume 等の指標は正規性を仮定しない。§8.5 の共通乱数により run 間の
  対応が取れる比較(比較対象5、6、7、9の間の比較)は
  **対応あり Wilcoxon 符号順位検定を既定とする**。共通乱数による対応が
  取れない比較(GP ベース手法など、実装上ソルバーの内部乱数系列が異なり
  candidate 対応が取れない比較対象3、ランダムサーチである比較対象1との比較)
  に限り、対応のない Mann-Whitney の U 検定を用いる。
- 有意水準は両側 5% とする。H1、H1b、H1c、H3、H4 は方向性を持つが、逆方向の
  有意差も報告価値があるため両側検定とする。ただし仮説の採択判定は
  「\(p < \alpha\) **かつ** 観測された効果の方向が事前に指定した方向と一致する」
  ことを条件とする。逆方向に有意な場合は、当該仮説を採択せず、逆方向の
  有意差として別途報告する。
- H3 の (i) 非劣性は、事前に定めたマージン \(\delta\) を用いた非劣性検定[13]で
  評価する。**\(\delta\) は比較対象5(baseline)の run 間ばらつきのみから
  決定し**、提案モデル(比較対象7)を含む観測差には依存させない。具体的には、
  予備実験で得た比較対象5の IGD+ の run 間標準偏差の一定倍(例: 0.5 SD)を
  \(\delta\) とし、本実験前に固定する。
- 仮説(H1、H1b、H1c、H3、H4)× 地形族にまたがる多重比較は Holm 法で補正する。
  検定族のサイズは「検証的仮説数 × 地形族数」とし、地形族数は §11 で
  事前に整数として固定する。
- 効果量として Vargha-Delaney の A12[14] を報告する。p 値のみによる解釈は
  行わない。

### 9.3 指標の事前定義

- hypervolume の参照点は、予備実験の全手法の観測目的値の nadir に一定
  マージンを加えた点として本実験前に固定し、以後変更しない。
- Pareto regret は、事前に固定した重みベクトル集合による augmented
  Tchebycheff スカラー化[15]の各重みにおける最良真値と、得られた解集合の
  最良値との差の平均として定義する。スカラー化に用いる目的値の正規化
  レンジ(各目的の最小・最大、または理想点・nadir 点)と augmented 項の
  係数 \(\rho\) は、重みベクトル集合および hypervolume 参照点と同時に
  本実験前に固定する。「最良真値」は §9.3 の参照 Pareto front に対する
  値であり、regret は近似参照 front に対する推定値であることを明記する。
- 参照 Pareto front は、小規模問題設定において高密度な真評価または列挙で
  近似し、近似手続きを記録する(実行可能性の見積りは §11)。
  **参照 Pareto front の近似、および §10 が定める最終候補解の再評価は、
  同一の hold-out combat seed 集合を用いる。** この seed 集合は最適化探索
  および代理モデルの学習には使用しない(§12)。

### 9.4 逸脱の扱い

本計画からの逸脱が生じた場合は、逸脱内容と理由を実験記録に残し、報告時に
明示する。

## 10. 主要評価指標

回帰精度は副次指標とし、真のシミュレーターで再評価した最適化品質を主指標とする。

### 最適化品質

- hypervolume および真評価回数に対する hypervolume の AUC
- hypervolume gap
- IGD+
- epsilon indicator
- Pareto regret(§9.3 の定義による)
- 真の非劣解に対する precision、recall
- 解集合の目的空間および配置空間での多様性

### 代理モデル品質

- 連続目的量: RMSE、MAE
- 確率目的量(勝率): Brier score および calibration(reliability 曲線、ECE)
- Spearman および Kendall 順位相関
- pairwise dominance accuracy
- top-k recall
- Pareto front 近傍に限定した局所誤差

### 計算効率

- 真のシミュレーション呼び出し回数
- シミュレーション、学習、推論、最適化を分けた実時間
- 所定の hypervolume 到達までの評価回数と実時間

最終候補解は代理モデルの予測値だけで評価せず、未使用の共通 seed 集合を用いて
真のシミュレーターで再評価する。

## 11. 第一段階の実験範囲

最初の実験では、参照 Pareto front を高密度な真評価または列挙で近似できる
小規模問題を用いる。片側 \(n\) セルの配置可能グリッドで \(k\) 対 \(k\) の
固定ユニット構成を考えると、配置候補数は概算で \(\binom{n}{k}^2\) となる。
例えば 4対4・片側 50 セルでは \(\binom{50}{4}^2 \approx 5 \times 10^{10}\)
通りとなり列挙は非現実的である。一方 2対2・片側 50 セルでは
\(\binom{50}{2}^2 \approx 1.5 \times 10^6\) 通り(× seed 数)であり、
列挙または高密度サンプリングが現実的な範囲に収まる。

> **要判断**: 第一段階の規模は次のとおりとすることを既定案とする。
>
> - **2対2の固定ユニット構成**(4対4は参照 front の近似が非現実的なため
>   第一段階の対象外とし、将来課題とする)
> - 片側 20〜30 セル程度の小さい離散配置グリッド(実行可能制約は §4.1 による)。
>   このとき候補数は \(\binom{20}{2}^2 \approx 3.6 \times 10^4\) 〜
>   \(\binom{30}{2}^2 \approx 1.8 \times 10^5\) 通りとなり、高密度サンプリング
>   による近似が実行可能である
> - **地形族数は 4 とする**(§9.1 の多重比較族サイズ、§9.2 の Holm 補正の
>   対象数を確定するため)。内訳は train 2、validation 1、test 1 を既定とし、
>   OOD 分割を要する仮説(H4)では別途地形族を追加する
> - 固定された戦闘ルール
> - 生成規則が明示された複数の地形族
> - 初期配置を主な決定変数とする2目的最適化(目的選定は §4.4 の基準による)
> - 各候補を複数の共通 combat seed で評価(seed 数は §8.5 の primary
>   configuration による)
> - scenario family 単位の train、validation、test、OOD 分割
>
> 想定シミュレーション回数は、参照 front 近似(高密度サンプリングまたは
> 部分列挙)、探索的検証的検定に用いる run(§9.1)、および最終再評価
> (§10)を合算して事前に見積もり、実験記録へ残す。

第一段階では、価値マップ型が常に優れることを前提にしない。検証的仮説の検定
(§9)と並行して、どの地形複雑度、学習データ量、評価予算、確率分散において
差が現れるか、または現れないかを探索的分析として明らかにする。詳細は §5 を
参照する。

## 12. BattleSimulator の役割と追加要件

現行シミュレーターは、明示的 seed、名前付き乱数系列、同時 tick 解決、
地形による移動・射線・damage への影響、version 付き結果、event log、
scenario family 単位のデータ分割を備えている。このため、真の評価関数と
データ生成器の第一版として利用できる。

### 12.1 既に利用可能な機能

`docs/current-spec.md` に記載のとおり、次は既存実装であり新規開発を要しない。

- 複数 seed による繰り返し評価と randomize 対象の指定
  (`Battle.simulate_k(k, randomize=...)`)
- scenario family 単位のパラメータスイープと trial ID による再開・重複排除
  (`run_batch()`)
- 勝率の不確実性区間と Monte Carlo 要約(`wilson_interval()`,
  `monte_carlo_summary()`)
- scenario family 単位の train/validation/test/OOD 分割
  (`scenario_family_partition()`)
- rules version・schema version 混在の検出(`validate_results()`)
- doctrine weights を含む固定長 scenario input features の
  `BattleResult` への保存(`docs/current-spec.md` の `BattleResult` 節)。
  ただしこれは集約統計量であり、価値マップ学習に必要な生の地形配列や
  初期配置の座標そのものではない(§12.2 で新規要件として扱う)

### 12.2 新規に必要な機能

価値マップ研究を開始する前に、少なくとも次の入力・記録機能を新規に追加する
必要がある。

- **離散配置グリッドと配置可能セル集合の入力**: 現行の `Composite.pos` は
  `Sampling` 分布による連続座標のサンプリングであり、§4.1・§11 が前提とする
  離散グリッドと配置可能制約は存在しない。決定論的なユニット初期座標を
  最適化変数として受け取り、実行可能制約(配置可能セル、重複禁止、
  チーム別領域)を検証する入力経路を追加する
- **地形高さ配列、初期配置座標、cover、objective の生データを学習用
  データへ保存する機能**: 現行の `BattleResult` が持つのは占有時間や
  損耗交換比などの集約統計量(§12.1)であり、価値マップ \(v_{\phi}(t)\)
  の学習に必要な地形高さ配列そのもの、および配置座標の生データは
  含まれない
- 局所的な地形介入(遮蔽物・高所・移動困難領域の追加と除去)を scenario の
  派生として定義・保存する機能(H5 用)
- **hold-out combat seed 集合の管理**: 参照 Pareto front の近似(§9.3)と
  最終候補解の再評価(§10)に使う seed 集合を、探索・学習用の seed 集合から
  明示的に分離し、両者が同一集合を参照することを保証する機能
- 参照 Pareto front 近似のための、決定論的な大規模 batch 実行の効率化
- 最適化器、代理モデル更新、infill selection の実験契約を定める

これらはシミュレーションの戦闘規則とは分離し、データ表現および最適化実験の
機能として実装する。

### 12.3 rules version への影響

上記 12.2 の追加(離散配置グリッド、実行可能制約、地形介入の派生定義、
hold-out seed 管理)は、AGENTS.md が定める「戦闘ロジックと可視化の変更は
分離する」方針に沿って、**`rules version 1.0` の戦闘意味論(移動、射程、
命中、damage、終了条件)を変更しない**データ表現・実験基盤の拡張として実装する。
これらの追加が意図せず既存 baseline の分布を動かす場合は、
`docs/simulation-rules.md` の Change Policy に従って rules version を
更新し、既存データセットの再生成が必要になることを明記する。

## 13. 主張範囲と妥当性上の制約

外部の実測データによる calibration がない間、代理モデルは BattleSimulator
`rules version 1.0` の emulator と位置づける。研究結果から、現実の戦闘、群集、
ロボット群に対する直接的な予測妥当性は主張しない。

第一段階で主張できる範囲は、次の内容に限定する。

- 定義した確率的多主体シミュレーターにおける結果
- 実験で用いた配置変数、地形族、ユニット数、評価予算の範囲
- §4.4 の基準により採用した目的対(§9.4 の逸脱記録がある場合はその内容を含む)
- 採用した多目的最適化手法、primary configuration とした infill 規則
  および評価予算配分(§8.4, §8.5)の結果を主張の根拠とし、他の水準の結果は
  感度分析として位置づける
- 未使用 seed による真評価で確認された探索性能

加えて、次の制約を明示する。

- 探索的分析(§5)の知見は仮説生成にとどまり、確認には独立実験を要する
- **提案モデルが H1b(§7)で解析的価値マップ基準(§8.1 比較対象6)を有意に
  上回らない場合、学習された価値マップの寄与は主張しない。** これは
  探索的な優劣判断ではなく、§9 の検定計画に従った事前登録済みの判定である
- 価値マップの因果的または人間可読な解釈は、H5(§7)の permutation test が
  対照条件に対して有意であった場合に限り、その範囲の弱い主張にとどめる。
  有意でない場合、価値マップの空間的な解釈可能性は主張しない

別分野への一般化可能性を論じる場合は、異なる相互作用規則を持つ追加環境、
または既存の空間シミュレーターを用いた追試を必要とする。
