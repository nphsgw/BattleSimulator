# 差分レビュー

実装とは別セッションで実行する。実装の経緯は渡さず、差分と基準（`AGENTS.md`、関連する `docs/`）だけを使う。

## 手順
1. `git diff HEAD` と未追跡ファイルを取得する。取得できなければ「判定不能」と報告し、問題なしにしない。
2. 変更ファイルに応じて観点別担当（`.claude/agents/`）へ同じ差分を渡し、並列で走らせる。
   - 戦闘・乱数・ID・順序に触れる: `determinism-reviewer`
   - 挙動・version・schema・docsに触れる: `spec-sync-reviewer`
   - `tests/` に触れる: `test-validity-reviewer`
   小さな変更は該当する担当だけでよい。
3. 結果を統合し、重複を除いてP0〜P2で報告する。

## 優先度
- P0: 仕様違反、再現性の破壊、検証の偽装。修正するまでマージしない
- P1: 境界・異常系・version更新の抜けの疑い。理由を記録すればスキップ可
- P2: 軽微。時間があれば直す

## 報告の決まり
- 各指摘に file:line、問題を起こす条件、根拠（`docs/` の節など）を付ける。推測は「要確認」と分ける
- 指摘が無くても、確認した観点を示す
- 静的に読んだだけの項目を、実行して確認した扱いにしない。挙動の確認は `make check` の結果で行う
- 今の要件にない汎用化・防御・抽象化は勧めない
- レビュー中はファイルを編集しない

## 終了条件
P0・P1が無ければ合格。3ラウンドで循環したら人間が裁定する。同種の指摘が繰り返されたら `AGENTS.md` / `docs/implementation-rules.md` への追加案として報告する（追加は人間が決める）。
